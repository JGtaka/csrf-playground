# CSRF学習シミュレーター 仕様書

## 1. プロダクト概要

クロスサイト・リクエスト・フォージェリ（CSRF）の仕組みを、ストーリー形式の体験を通じて初学者が直感的に理解できる教育用Webアプリケーション。架空のSNS「Chirpy」を題材に、攻撃が成立するまでの流れと防御手法を可視化する。

- **ターゲットユーザー**：Web開発を学び始めた初学者、セキュリティ教育を受ける学生・新人エンジニア
- **コアバリュー**：受動的に読むのではなく、ステップを進めながら攻撃の流れを「体験」できる

## 2. 画面構成

アプリケーションは2画面構成。

### 2.1 トップページ（ランディング）

| エリア | 内容 |
| --- | --- |
| ヘッダー | ロゴ「CSRF シミュレーター」／「ログイン」「シミュレーション開始」ボタン |
| ヒーローセクション | キャッチコピー「CSRF攻撃の仕組みを体験して学ぶ」／概要説明文／CTAボタン「シミュレーションを開始する」／攻撃イメージビジュアル |
| メッセージセクション | 学習意義を伝えるブロック「セキュリティの知識を、一生の武器に。」／CTAボタン「今すぐ学習をスタート」 |
| フッター | 利用規約／プライバシーポリシー／セキュリティガイドライン／お問い合わせ |

### 2.2 シミュレーターページ（ストーリー型）

スマートフォン風フレームを画面中央に配置し、左右に解説カードを置くシンプルな3カラム構成。サイドバー・上部ナビゲーションは持たない。

| エリア | 内容 |
| --- | --- |
| 中央：スマホフレーム | 現在のステップに対応するシーンを表示（ログイン画面／罠サイト／リクエスト送信／結果） |
| 左カード | そのステップの「裏側で起きていること」を解説 |
| 右カード（上） | HTTP Request / Cookie / 攻撃コードなど技術的な内部情報 |
| 右カード（下） | Countermeasures（防御策） |
| 下部コントロール | ステップインジケーター（1/4 等）／「Reset」／「Next Step」ボタン |

## 3. ストーリー構成（4ステップ）

| Step | タイトル | 中央スマホ表示 | 左カード（解説） | 右カード（技術詳細） |
| --- | --- | --- | --- | --- |
| 1 | Authentic Login | Chirpyにログイン成功 | セッションCookieが保存される仕組み | 保存されたCookieの内容（ドメイン・属性） |
| 2 | Visit Trap Site | 罠サイトを開く（猫画像のおとり） | 罠サイトに仕込まれた隠しフォーム／自動実行JS | 罠サイトのHTML/JSコード |
| 3 | Forged Request | リクエストが自動送信される | Cookieが自動付与される仕組み（CSRF核心） | 偽装されたPOSTリクエスト（Origin不一致） |
| 4 | Damage & Defense | 攻撃成立／投稿が改ざんされる | 被害の説明と防御の必要性 | 各防御策の解説（SameSite／CSRFトークン／カスタムヘッダー） |

## 4. 画面遷移

```
[トップページ]
   │
   ├─「シミュレーション開始」ボタン
   ├─「シミュレーションを開始する」ボタン
   └─「今すぐ学習をスタート」ボタン
              │
              ▼
       [シミュレーターページ Step 1]
              │
        Next Step（順方向のみ進行）
              ▼
       [Step 2] → [Step 3] → [Step 4]
              │
              ├─ Reset → Step 1へ戻る
              └─（最終ステップ）→ 完了状態表示／トップへ戻るリンク
```

## 5. 主要機能

### 5.1 ステップ進行機能

- 「Next Step」ボタンでステップを1つ進める
- ステップ変更に応じて、中央スマホ／左カード／右カード上下が同期して切り替わる
- 切り替え時は短いフェード・スライドアニメーションで視覚的連続性を保つ

### 5.2 リセット機能

- 任意のタイミングで Step 1 に戻せる

### 5.3 ステップインジケーター

- 現在位置を「Step X / 4」形式と進捗ドット（● ○ ○ ○）で表示

### 5.4 解説の文脈追従

- 右カードの「HTTP Request」「Countermeasures」は、現在のステップに関連する内容のみ表示する（全ステップ共通の固定表示にしない）
- 例：Step 1 では Cookie の保存内容、Step 3 では偽装リクエストの中身、Step 4 では防御策の解説、というように切り替える

## 7. 非機能要件

- **レスポンシブ対応**：デスクトップ優先、タブレットまで対応。スマホ実機ではフレーム比率を縮小して表示
- **アクセシビリティ**：ボタンに適切な aria-label、キーボード操作可能
- **パフォーマンス**：画像は最適化、初期ロードは軽量に
- **言語**：日本語UI（コード例・HTTP/技術用語は英語のまま）
